\### 4. How the Persistent Flow Works Now



| Step | What happens |

|------|--------------|

| \*\*Login\*\* | Server sets `access\_token` (15 min) + `refresh\_token` (30–180 days) as \*\*persistent\*\* httpOnly cookies. |

| \*\*Active use\*\* | Frontend calls `/refresh` every 14 minutes. Old refresh token is burned; a new one is issued. |

| \*\*Close browser → reopen\*\* | Cookies survive because `max\_age` is set (not a session cookie). On reopen, the frontend calls `/refresh` and gets a fresh access token. |

| \*\*Switch browser / device\*\* | Cookies are isolated per browser. The new browser has no tokens → user must log in. |

| \*\*Explicit logout\*\* | Server revokes the DB session and clears both cookies. All other rotated refresh tokens for that session chain are already invalid. |
